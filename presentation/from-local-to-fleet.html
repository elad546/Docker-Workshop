From Local to Fleet:
Mastering Modern Containerization

Solving the "Works on My Machine" Problem with Docker

  • Packages code, libraries, and config into one portable unit
  • Same artifact on laptop, CI, staging, and production
Open with the pain everyone knows. Docker is packaging and delivery — not just virtualization.

"It Works on My Machine"

  • Conflict — version and OS drift between dev and prod
  • Cost — debugging mismatch, failed deploys, downtime
  • Solution — one image runs the same everywhere
Keep it relatable. Reproducible environments beat better dependency docs.

Blueprints vs. Living Instances

  • Image — read-only template (Class)
  • Container — running instance (Object)
OOP analogy lands fast. Pull from Docker Hub, build from Dockerfile, push to share.

Why Containers are Lightweight

  • VMs — full guest OS each; heavy and slow
  • Containers — share the host kernel; dense and fast
Containers isolate processes, not hardware. Many more workloads per host.

How Docker Works

  • Client — commands you type (docker run, docker buildx)
  • Daemon — manages images, containers, networks
  • Registry — stores and shares images
Client talks to dockerd via socket. Module 0 installs and verifies the daemon.

Modules 1–2: The First Container hello-docker

docker buildx build --load \
  -t hello-docker:1.0 .
docker run -d --name hello \
  -p 8080:80 hello-docker:1.0
  • Build — Dockerfile + nginx:alpine
  • Verify — curl localhost:8080
Buildx with --load. Port 8080 on host maps to nginx port 80 inside the container.

Modules 2–4: Inside & Manage

docker exec -it hello sh
docker logs hello
docker ps -a
docker stop hello && docker rm -f hello
docker rmi hello-docker:1.0
  • Exec — explore a live container
  • Housekeeping — stop, rm, rmi
  • Optional — docker commit (Module 3)
Alpine uses sh, not bash. Remove container before removing its image.

Module 5: Multi-Container Stacks compose-demo

  • Compose — web + API + Redis in one YAML file
  • Networks — frontend / backend bridge isolation
  • Test — curl localhost:8081/api/health
redis_hits increments on repeated curls. Tear down with docker compose down --volumes.

Security First with Podman

  • Risk — Docker's root-privileged daemon = larger attack surface
  • Podman — daemonless, rootless; containers as user processes
  • Plus — native systemd unit integration on Linux
Podman is largely CLI-compatible with Docker for many workflows.

Managing Fleets with Kubernetes

  • Self-healing — restarts failed pods automatically
  • Auto-scaling — grows/shrinks with demand
  • Compose for dev · K8s for production fleets
